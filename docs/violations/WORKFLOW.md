# 違反・改善措置

候補の登録と正式違反の確定は別操作です。AI候補はConfidence・実行元・原本hashを保持し、査察指摘や正式データを上書きしません。

1. 「違反・改善措置」から候補を登録。対象物、任意の査察指摘、確認日、問題点、不足情報、必要確認を入力します。根拠は検索し、選択します。複数原本は再選択で解除できます。
2. 正式違反のHuman確認には、承認済・有効日のRuleと一次資料の構造化条文引用、証拠原本、正式手続原本が必要です。確認と正式確定は別操作で、それぞれ理由とHuman確認を要求します。
3. 指導は正式違反未確定でも登録できます。命令・処分は正式違反確定と手続原本を必要とし、措置自体にも確認・確定があります。
4. 改善指示と期限を登録。未確定案件は確定済指導へ関連付けます。回答原本を記録し、Humanが肯定/否定の確認を行います。完了には肯定的確認と完了証拠が必要です。
5. 指示・期限の変更や新回答後は再確認が必要です。回答から確認・完了までの全原本hashを再照合します。履歴は追記し、過去イベントを変更しません。
6. 全ての有効な改善措置が完了した場合に、Humanが案件を完了できます。指導だけの改善は「指導による改善済（正式違反未確定）」として残ります。取消だけ・指示なしでは完了できません。
7. 正式履歴の訂正は改訂候補で行います。新たなHuman確定まで元の正式履歴を保持します。未完了の改善や有効な命令/処分がある間は案件撤回・置換を拒否します。

期限一覧は指定日より前の未完了指示をページ送りで表示します。横断検索から案件へ戻れます。CSVは案件・措置・改善・履歴を別に出力し、原本/法令閲覧権限を適用、監査を記録します。原本は権限・本人・画面状態を再確認して保存します。

| 初期ロール | 操作 |
|---|---|
| violation_editor | 候補・草案・改善指示・回答・訂正・取消・CSV。正式Human確定不可 |
| violation_reviewer | 参照・Human確認・正式確定・完了・措置撤回。候補登録不可 |

初期ロールは共通職員・有効日権限管理で割り当てます。異動、セッション失効、権限喪失時は共通mutation guardが書込みを拒否します。競合・根拠変更409は最新情報の再読込とHuman再確認で解決します。

本資料のテスト例は合成データです。実案件への法的措置・正式条文採用・Human手続の適法性をAIが代行しません。実一次資料の組織承認と実LAN受入は別のExternal Gateです。

完了済み案件でも、有効な命令・処分を自動解消しません。新しい案件で正式置換する前に、完了済み案件の「措置原本・手続」画面から承認者が証拠付き撤回を行います。撤回理由・原本・Human actorは履歴に残ります。承認済の条文引用と現在のcanonical全文が異なる場合、法令Rule自体のHuman改訂・再承認が必要です。
