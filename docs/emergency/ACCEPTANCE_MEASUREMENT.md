# 救急報告書チェック：5指標の測定・受入仕様

基準日: 2026-11-21（日本時間）。利用者が指定した5指標を実装可能な契約にする。下記の構成・測定方法は今回の設計判断であり、未測定の性能値や本部の承認を表すものではない。

## 目的と境界

提出後の訂正を減らしたことを、同条件の導入前後の記録で確かめる。既存の本部固定・認証・権限・監査基盤を使う。別の集計アプリに分断せず、原本を含まない評価記録をサーバーに保存する。原本や患者の値を一般の評価入力へ持ち込まない。

採用するのは「独立確認済みの測定記録を保存し、計算結果と証拠不足を分けて表示する」方式。訂正済みの帳票だけを正解とする方式や、AI自身の回答を正解にする方式では見逃しを測れない。現行の候補ルール、正式様式の対応、OCRの実帳票精度は既存ロードマップの承認を待つ。新機能は正式提出可否を確定しない。

監査システムでは、原本版に結び付いた不変の検査履歴、担当者が記録した提出・作業・追跡の事実、別職員による正解確認から評価入力を生成する。所定の形式による手動の測定記録も引き続き扱う。どちらの経路でも、以下の対象範囲・重複処理・未確定の扱いをそろえる。

## 指標

| 指標 | 算出と必要条件 |
| --- | --- |
| 提出後訂正率 | 観察完了した報告書のうち、評価対象の誤りで訂正された件数 / 観察完了件数。追跡中・不明は件数を別掲。前後の差はポイント差と相対削減率を分ける。導入前0%なら相対削減率は算出しない。 |
| 提出前の誤り発見率 | 対象範囲にある固有の実際の誤りのうち、提出前に警告された誤り / 独立確認で確定した固有の実際の誤り。読取不能・未検査にある誤りや、対象原本を提出後に検査して初めて分かった誤りも分母に含む。同一誤りへの複数警告を重複成功にせず、提出後の発見を提出前の成功にしない。 |
| 誤警告 | 独立評価済み報告書1件当たりの、提出前に生成された誤警告数を主指標とし、提出前の警告のうち誤警告の割合を併記。対象内の再検査で繰り返した警告も、検査ごとの負担として数える。提出後の警告は別掲し、この割合に混ぜない。警告0件の割合は算出不能で、0%と表示しない。発見率と同時に評価する。 |
| 合計作業時間 | 取込、読取確認、点検、訂正、再検査、別担当者の確認、提出後訂正に要した人・分。職員ごとの重複時間を拒否し、別職員の同時作業は合算。欠測と実測0を区別する。平均・中央値・件数・欠測を表示する。 |
| 読取・未検査と保護 | 読取状態と検査状態を別軸にし、独立確認との一致、未検査、読取不能、誤った「問題なし」を表示する。個人情報保護は平均点へ混ぜず、本部の対象環境・版に対応した独立確認の証拠を要する。 |

単純な前後差だけからAIの因果効果を断定しない。対象様式・事案構成・確認担当・追跡期間・作業範囲と、評価に含める原本版・検査履歴の条件をそろえる。評価記録は原本との内部対応表を本部内で保持し、無作為な評価IDで参照する。

## 評価対象となる原本版と検査履歴

監査連携では、担当者が記録した実際の提出日時を基準にする。原本版の取込・登録時刻 `AuditRevision.created_at` が、その提出日時以前である検査履歴をすべて対象にする。同一原本への再検査と、提出前に取り込んだ複数の原本版を含む。原本版の登録時刻は、帳票本文に書かれた作成日やファイル名から推測した日付ではない。

| 原本版と検査の関係 | 誤り・警告・読取状態の検査機会の扱い |
| --- | --- |
| 提出日時以前に登録した原本版への、提出前の検査 | 対象に含める。警告の登録時刻が提出日時より前なら、提出前の警告とする。 |
| 同じ対象原本版への、提出日時以後の検査 | 対象に含める。提出後に分かった実際の誤りを見逃さず記録するが、その警告を提出前の発見数には加えない。 |
| 提出後に新しく登録した訂正版・差替え原本への検査 | 提出前の誤り発見率・誤警告等の検査機会には含めない。提出後に生じた誤りを過去の分母へ追加しない。原本と全検査履歴は残す。 |
| 提出日時が未登録 | 対象範囲と警告の提出前後を推測しない。警告の時点を確定できない測定は保留し、未確定を「提出後」として埋めない。 |

警告の時刻には、その不変の検査履歴の登録時刻を使う。提出日時と同時刻の警告も、提出前の成功としては扱わない。報告書詳細の `measurement_scope` に対象の検査数、提出後の新原本に属する検査数、全検査数を表示する。対象外の原本版があっても、記録された作業区間と提出後の訂正・追跡結果は残し、合計作業時間と提出後訂正率の記録から除かない。

検査機会と実際の誤りは別に数える。対象内の検査履歴ごとに警告機会を保持し、再検査で同じ誤警告を繰り返せば各回を数える。画面を再表示した回数を数えるものではない。一方、同じ実際の誤りには、独立確認者が同じ `error_id` を割り当てる。ルールとAIの両方が同じ誤りを指摘した場合も、発見率の誤り数を増やさない。本文の類似だけでAIが同一誤りと決めず、別の報告書に同じ誤りIDを流用しない。

`report_version` は、対象内で最初の検査履歴が参照する基準原本版の番号である。すべての検査機会がその1枚・その1版だけから得られたという意味ではなく、報告書全体の編集回数でもない。対象の検査履歴がない場合は現在の原本版を使うが、検査済みにはしない。各機会と実際に使った原本版の対応は、本部内の検査履歴・内部対応表で確認する。

## データと状態

- 評価データ区分は合成テスト / 本部内実測。初期設定で本部内実測の登録を無効にし、承認された内部環境でのみ設定を有効にする。この設定自体は安全性の証明ではない。
- 評価には、無作為な報告書ID・基準原本版・比較群・事案区分・読取方式・観察完了状態・独立確認状態・検査機会・作業区間を持つ。氏名、住所、診断文、OCR原文、原本ファイル名を受け付ける欄は設けない。同じ評価入力に同じ報告書を別の行として重複登録しない。
- 検査機会は固有ID、正解（誤り / 正しい / 不明 / 対象外）、固有の誤りID、警告の有無、提出前か、表示された読取状態、独立確認した読取状態を持つ。
- 読取状態は確認済み / 未確認 / 読取不能 / 非印字 / 未対応。確認済み空欄と非印字を混同しない。判定は警告 / 検査済み問題検出なし / 未検査 / 対象外。
- 評価は不変のスナップショットとして保存する。訂正時は以前の評価を指定して新版を作る。前版を上書きしない。再送は同じ要求IDに限り同じ記録を返し、異なる内容なら競合にする。
- 数値目標、最低標本数、比較条件が未設定・未確認なら判定を保留する。根拠が不明な記録を都合よく分母から除外して合格させない。

入力形式の正本は `backend/app/emergency_acceptance_schemas.py`。監査履歴からの対象選択と評価入力の生成は `backend/app/emergency_audit_workflow.py` の `metric_scope` と `measurement`、指標計算は `backend/app/emergency_acceptance.py` に対応する。手動記録もこの入力契約を使用し、[運用手順](ACCEPTANCE_OPERATION.md)に従って保存・独立確認する。手動で入力できることは、提出日時や誤りの正解を補ってよいという意味ではない。

正解は、作成者とは別の職員が各対象検査に対応する原本全体と各確認項目を見て確定する。訂正が入った事実、作成者の警告対応、AIの候補だけで正解を自動確定しない。対象内の検査に独立確認の未完了が残れば、報告書全体を確認済みにしない。未確定の正解や読取状態はそのまま残す。

未確認の警告や未確認の報告書がある場合、確定済みの一部だけを分母にして誤警告割合を確定しない。警告時点や対象範囲が未確定の記録、上限超過で全機会を保持できない測定を、都合のよい部分だけ切り取って完成扱いにしない。作業時間も、実際に記録した区間と担当者の計測完了確認を使い、記録がない時間を0分で埋めない。

## 受入・安全の境界

計算結果は「未測定 / データ不足 / 目標未設定 / 判定保留 / 未達 / 数値目標達成」を使い分ける。合成データには常に「開発検証のみ」を付ける。全指標の数値が達成しても、それだけで本番完成や提出許可を出さない。

最終受入には、少なくとも現行正式ルール、様式対応、独立した実帳票評価、訂正から再読込までの実操作、対象環境での外部通信・権限・保存と原本分離・ログ/一時ファイル・バックアップ復元の証拠を要する。登録者とは別の責任者が、固定された評価版と証拠の対応を確認する。自己申告の「安全」チェックだけで完成へ変更できるAPIは設けない。

本変更で完成を証明できないもの: 正式資料の組織承認、未確定の様式対応、実帳票のOCR/手書き精度、本部実機の通信と復旧、実運用での訂正削減。未検証は結果画面と保存記録に残す。正式な本番承認は既存ロードマップP18で別に行う。

## 検証

0分母・導入前0・警告0・未確定・未読による見逃し・重複誤り・再検査での警告の繰返し・対象原本への提出後検査・提出後に登録した新原本の除外・提出日時未登録・時間重複・不正型・個人情報のエラー反射・未認証/権限不足・失効・再送・独立確認・古い版の競合・共有端末の応答競合を合成データで検証する。実測値をこの公開リポジトリへ保存しない。
