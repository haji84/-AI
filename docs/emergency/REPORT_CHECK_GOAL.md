# 救急報告書チェックAI: 正式GOALと開発ゲート

## 最終GOAL

組織が承認した内部環境で、実際の救急報告書を安全に読み取り、正式な現行入力要領の条件・例外と照らし合わせ、入力した本人が提出前に問題候補の理由と根拠を確認し、原システムで訂正して再確認できるシステムを完成させる。

- 通常操作は「原本を開く → 確認が必要な箇所を見る → 本人が原システムで訂正 → 再チェック」。大量の設定・確認項目を最初から本人に要求しない。
- 機械ルール判定とAIの文章矛盾候補を分離する。AIは正式判断、医療上の判断、訂正の確定を代行しない。
- 入力画面、共通項目ID、印刷PDFの3層で対応を管理する。表示変換や非印刷項目を考慮する。PDFに印字されない値を空欄や合格と決めつけない。
- 新様式の指定された事故種別2欄は一致確認する。ただし別台帳間の事故種別を無条件に同一扱いしない。
- 不搬送は緊急度を入力しない、転院搬送は準緊急（黄）、住宅以外は発生階層・小分類を入力しない等、空欄が正しい例外を優先する。
- バイタルの医学的な参考範囲と年齢別の緊急（赤）判定基準は区別する。数値だけで緊急度の総合判断を否定しない。
- 二重線や手書き訂正を含む原本の一括取込は、訂正箇所・前後・理由の抽出後、人の確認と正式要領との照合を経る。訂正事例から勝手に正規ルールを作らない。重複防止、中断再開、評価とロールバックを設ける。
- 本人向け結果では「確認済み」「要確認」「未検査」「対象外」を区別し、未検査を合格と表示しない。
- 実原本、OCR派生物、学習例、モデル入力、バックアップはGitHubや外部AIに送らない。組織の承認を得た内部環境で専用権限、監査、暗号化、復元検証を行う。
- 正式完成判定は、現行正式ルールの承認、認証／権限、実帳票の読取精度、訂正ループ、実ブラウザと実機、誤指摘／見逃しの測定、安全な停止復旧を検証した後のみ。

## 今回の実装（候補判定核・非本番）

- backend/app/emergency_review_core.py は、人が確認済みの正規化された値だけを使い、個人情報を含めずに確認候補を返す純粋関数。
- PDFの読取、手書きOCR、API、RBAC、DB、画面、一括学習は今回の変更では未接続。
- 読み取れない・未確認・未対応・印刷されない項目は NOT_TESTED を返す。
- ルールはすべて PROVISIONAL_NOT_APPROVED。NO_ISSUE_DETECTED も正式適合の保証ではない。

### 最初の確認対象

| 候補 | 根拠 | 重要な例外 |
| --- | --- | --- |
| 不搬送の緊急度は空欄 | 全国版入力要領p9、利用者提示の運用 | 印刷されない値を空欄と扱わない |
| 転院搬送の緊急度は準緊急 | 全国版p14、地域版p17 | 不搬送を先に判定する |
| 発生場所の小分類・発生階層 | 全国版p10、地域版p14 | 住宅以外は空欄。住宅の発生階層の空欄を勝手に違反扱いしない |
| 新様式の事故種別2欄一致 | 利用者提示の運用 | 新様式の厳密な2欄位置／コード未確認、別台帳間とは区別 |
| 年齢別の緊急（赤）数値トリガー | 地域版p17 | 転院搬送・不搬送を除外、測定時点と年齢区分を固定、医学的な正常値ではない |

資料はユーザー提供の全国版48ページ（表紙の対象期間2021-2022年）と地域版28ページ（2026年1月作成の参考資料）。原本はGitHubに含めない。正式な現行運用の裏付けが取れるまで、候補のみ。
