# 車両の現在配属とHuman記録

仕様23の車両台帳に、既存組織への現在配属・明示的な未配属・変更履歴を追加する限定範囲です。基準mainは `71754c593066cd2720178372fcf0c8c4620aab50`。配車や出動、職員の勤務・所属を自動変更しません。

## 使用手順

1. 必要に応じて、権限を持つ管理者が既存の職員・組織管理画面で有効な組織を登録します。車両画面から組織や職員を新規作成しません。
2. `fleet.read` を持つ職員が「事案・車両」→「車両」から既存車両の詳細を開きます。配属履歴がない場合は「未記録」であり、正式な未配属とは区別します。
3. `fleet.update` も持つ職員が「配属を記録・訂正」を開き、組織名・コードで検索して配属先を選びます。配属を解除する場合は「未配属をHuman確認」を明示的に選びます。
4. 変更前後、変更・確認の理由、根拠となる参照情報を確認し、Humanとして確認したチェックを付けて保存します。理由・参照情報は仕様5.2の訂正履歴契約に従います。記録者・時刻・前後の版はサーバーが自動記録します。
5. 競合時は下書きを保持した再読込から、最新の車両・組織と変更内容を再確認します。保存済み後の表示取得に失敗した場合は読込みを再試行し、同じ保存を繰り返しません。送信後の「戻る」は、サーバーへ送信済みの変更を取り消す操作ではありません。

参照情報は職員が記録する根拠の説明です。この範囲ではDocument原本へのリンクやバイト列・ハッシュ照合を実装しておらず、「原本検証済み」とは扱いません。Human確認は管理職による正式承認や新しい承認階層を意味しません。

## 保持する事実と権限

- 現在配属は追記履歴の車両版の順序から導出します。車両の版更新と履歴・監査記録は同じtransactionです。同じ版への競合・繰り返し送信は拒否します。
- 組織の名称・コード・版を履歴に固定保存します。後の名称変更や無効化で過去を書き換えません。新たな配属先は有効な組織から選びます。
- 車両の「休止」は配属と別の事実です。休止による自動移動・自動解除は行わず、明示的な台帳訂正を保持します。
- 組織候補は現在の本部DB内のID・コード・名称・版だけです。人事管理、職員一覧、組織階層や別本部の情報へアクセスを広げません。
- 更新時は現在のセッション・アカウント・役割と `fleet.update` / `fleet.read` を再検証します。一般監査には必要な識別情報と根拠のdigestを記録し、参照情報の本文は車両権限で保護された履歴に保持します。
- 古い画面や保存応答が新しい配属の下書きを上書きしないよう、表示の所有権・Close・新しい移動・ログアウトを確認します。既存の事案/車両業務APIの意味は変えません。

## 検証記録

APIと実際の画面/SharedSessionソースを使い、未記録→配属→転属→未配属、名称変更、休止、権限不足、古い版、重複操作、下書き保持、遅い応答、Close・再ログイン、保存成功後の表示失敗を確認しています。独立レビューで見つかった古い一覧/警告応答による下書き消失と、現在の保存後エラーが隠れる問題を再現して修正しました。

backend単体の全体実行は881件成功・244件スキップ。main b0a14a8上のbackend/画面統合では913件成功・255件スキップでした。71754c5への最終統合と、実PostgreSQL・Chromiumはその候補の正確なheadに対するCIで別途確認します。ローカルではChromiumを起動していません。

## 残る範囲

配属のCSV/XLSX取込・出力拡張、配属を使った横断検索、直接原本連携は未実装です。将来/遡及/一時/複数配属や正式な別承認者の方針は追加していません。仕様23全体の完了、本部実機受入、本番導入を意味せず、章の状態はPartialのままです。
