# 期間を指定した観測統計

仕様34の最初の限定範囲です。既存main `71754c593066cd2720178372fcf0c8c4620aab50` の救急・事案/出動・車両運行記録を読み、観測値の保存・Human確認・汎用CSV/XLSXを追加します。停止した旧作業環境からの回収コードではありません。元の業務記録を変更せず、統計のための二重入力を要求しません。

## 使い方

1. ログイン後の「観測統計」から、開始日・終了日と現在の権限で利用できる指標を選びます。日付は両端を含み、年度や通貨を自動推定しません。
2. 「観測プレビュー」で、指標ごとの定義・単位・日付基準・除外件数・制限を確認します。救急事案件数、傷病者記録数、活動事案件数、出動記録数、承認済出動記録数、車両運行記録数、運行距離を別々に表示します。傷病者記録数は実人数ではなく、出動や運行を事案数へ加算しません。
3. 保存はその時点で元データを再取得します。直前のプレビューがそのまま保存される保証ではありません。保存後の値と条件は固定し、後の元データ訂正で自動上書きしません。
4. 保存記録からHuman確認を行います。確認直前に同じ条件の元データを照合し、新たな対象・日付変更・関連記録の追加などで根拠が変わった場合は拒否します。必要なら理由を記録して「新しい保存版」を作成し、以前の値・確認履歴を残します。
5. 「汎用CSV」「汎用XLSX」は保存された値を出力します。元記録の参照は別途その業務の個票権限で確認し、現在の元記録画面を開きます。元記録は保存後に更新されている場合があります。

「Human確認済み」は観測値・定義・制限を職員が確認した意味です。正式な承認者による承認、公式統計としての完全性、欠測がないことを意味しません。網羅性は確認後も `unknown` のままです。観測値0、利用不可、不明を混同しません。

## 日付と時刻

統計専用のサーバー設定 `FIRE_AI_STATISTICS_BUSINESS_TIMEZONE` は有効なIANA名を受け付け、日本の本部向け既定値を明示的に `Asia/Tokyo` とします。ブラウザの場所やUTC保存を業務日として推定しません。選択日付・zone・開始UTC時刻・終了翌日UTC時刻・日付基準の版を保存し、終了翌日未満の範囲でtimestampを選びます。DATEの救急覚知日は日付のまま扱います。保存後の確認・新しい保存版は固定済みの期間境界を使用します。

PostgreSQLでは記録されたtimestampの瞬間を使いますが、元の入力者が意図した時刻帯まで復元した証明にはなりません。SQLite開発環境では、現行のUTC正規化を通る登録経路の成功監査を確認できる事案/運行だけを保守的に採用します。監査は過去のschemaや時刻そのものを証明せず、未確認の旧データや直接SQL変更の安全性を保証しません。確認できない時刻やSQLiteの連携火災時刻は除外し、件数・根拠を保持します。このため過少集計の可能性があります。

日付不明などの除外件数は、本部内の全期間の未確定候補です。選択期間に属する件数と推定しません。従来の各モジュールの集計APIの日付契約は変更しません。

## 権限と保存する根拠

- 統計の閲覧・記録・出力は `statistics.read` / `statistics.record` / `statistics.export` を使い、選んだ元業務の集計権限も必要です。出力には元業務の出力権限も必要です。保存時の権限を将来の閲覧権限として使いません。
- 初期seedは、既存契約に従い本部内の `system_admin` のみに統計権限を追加します。一般Roleは自動変更しません。必要な職員への付与は、権限を持つHumanが既存の「自分の権限・Human権限管理」で本部Roleを明示設定します。サービス運営者や別本部への権限ではありません。
- 集計だけを許可された職員は個票権限なしで観測統計を使えます。患者・職員・事案・出動・運行のIDや個別hash、私的な根拠本文は集計応答・出力・一般監査へ含めません。個票参照は別に元業務の権限を検証します。
- 内部には、値の算出と同じ対象集合・関連行・除外行の根拠を保存します。公開checksumは安全な公開値だけに基づき、私的な行一覧のfingerprintを公開しません。
- 同一の本部DBに束縛された読取りsnapshotで取得し、その後の新しいtransactionで元のログインsession・パスワード状態・アカウント・現在の全権限を再確認します。確認時の鮮度は取得時点のものです。業務全体を固定して、その後の元記録更新まで止める仕組みではありません。
- 保存値・根拠は不変で、Human操作履歴は追記します。新しい保存版は別IDとなり、競合した確認・置換は版照合で拒否します。別本部を選ぶ入力はありません。

## 検証と残る範囲

独立レビュー、実PostgreSQLのsnapshot・保守・本部分離・同時更新、実Chromiumの業務操作は候補の正確なheadで別途検証します。ローカルでスキップしたPostgreSQL/Chromiumを成功件数として扱いません。

この範囲の出力は「汎用統計出力（正式様式ではありません）」です。登録済み原本様式への出力、比較可能な前年・年度集計、網羅性の宣言/承認、過去と現在の人員・車両母数、財務の正確な通貨別集計、査察・届出・設備など残りのsource adapterは未実装です。汎用XLSXのバイト列が毎回同じになることも保証しません。仕様34全体や製品全体の完成、本部実機受入、本番導入を意味しません。
