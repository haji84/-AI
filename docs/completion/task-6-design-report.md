# Task 6 design — evidence-required council inquiries

The application retains its existing tenant-bound Session, common Employee/User/Document UUIDs, RBAC, audit trail, module registry, shared PC shell and original-template renderer. `/inquiries` adds questions, separate answer drafts, live source snapshots, explicit numerical claims, model candidates, Human review and immutable approved revisions.

## Authority and evidence

`Inquiry` owns versioned question/year/draft/claims and Human timestamps. `InquiryEvidence` stores typed source identity, original Document UUID/SHA, record version, source date, query parameters, retrieved verbatim excerpt, exact value/unit strings, content hash and required source permissions. Sources are server-selected fields from existing models or text extracted through the common original extractor. A caller cannot supply an authoritative number, source SHA, record version or fabricated quotation. A changed/missing source blocks confirmation.

Exact numbers are decimal strings in JSON; calculations use Decimal with bounded input and a declared identity/sum/difference/product/quotient expression. Every numeric literal in answer prose must match an inquiry-bound source value/unit or the exact declared result. Full-width digits, leading decimals, Unicode mathematical minus, grouped decimals and scientific notation normalize without binary floats. Unsupported fraction notation, ambiguous decimal separators/grouping and dash-like signs fail closed in both source and answer text. Complete UUID identifiers and non-quantity digest tokens are excluded from numeric quantity parsing. A scientific literal, including a recognized adjacent unit, is never exempted as a digest; ambiguous metadata remains fail closed. Written-number assertions and fraction glyphs fail closed and must be expressed as explicit digit decimal claims. Exact division rejects non-terminating results; it never silently rounds. Narrative correspondence is explicitly confirmed by a Human.

Draft edits and evidence changes invalidate review. Review locks the answer and source records, validates the complete evidence/claim snapshot, and stores reviewer identity/time. Approval requires unchanged explicit review. Approved answers have no edit/delete path: an additive revision copies the evidence/claims into a new draft and preserves the approved parent. PostgreSQL migration triggers preserve approved rows and evidence snapshots even against direct DML.

## Confidentiality

Permission checks precede all derived question/answer content, evidence, candidates and counts. Lists, year filters, lexical similarity, unified search and export omit an entire record when any relevant source is restricted. Detail/actions deny access. Historical source permissions remain in cumulative lineage when evidence is removed, so deleting a citation cannot declassify prose or an older candidate. Source Document associations are rechecked for newly added restrictions. An iterative closure follows import ownership, inquiry historical/current source links, rendered parent and historical/current template originals, processing every local permission before marking nodes visited; cyclic graphs terminate without omitting restrictions. Render manifests persist template-source permissions as well as original SHA/UUID, so outputs retain snapshot restrictions after associations change. Generic audit.read has no inquiry/source rights, so inquiry audit events contain only fixed metadata, counts and change/source hashes; raw before/after prose, values, reasons, input snapshots and adapter labels remain outside the generic audit payload. Model versions in generic audit are hashed; authorized inquiry/candidate records retain complete provenance.

A narrow `guard_document` protects inquiry-created import originals and rendered forms in the existing common Document metadata/download and unified search paths, finance extraction/pickers, and intake extraction/read/review/application paths. Unrelated originals retain their existing behavior. Mixed-record import originals retain the union of source permissions across their rows.

## Candidates, exchange and UI

`local_model_adapter` is an optional in-process adapter accepting exact authorized source snapshots and returning bounded draft/claims/model/version/confidence. Candidate text, input provenance and generation time are stored separately. Adopting a candidate validates its input version and evidence again, produces only a draft, and requires separate Human review/approval. The deterministic fallback quotes selected evidence and is explicitly labeled; no semantic-accuracy claim is made. Adapter outage returns an actionable error while manual CRUD/evidence/search continue. Model work uses deep-copied inputs outside canonical mutation locks, then revalidates session, permissions, inquiry version and live sources within the short persistence gate.

CSV/Excel use an exact `inquiries-v1` schema. All rows, quotes, claims and source snapshots validate within one request transaction before a common original is stored. Imported official/reviewer/model history is non-authoritative metadata; imported answers remain drafts. Tabular CSV/Excel export uses reversible apostrophe neutralization. Finite JSON cells are bounded by depth and content before the canonical write gate; exact source-number exponents are bounded before decimal expansion. Original-template output uses only an active `inquiries` fill-only common FormTemplate with verified original SHA; it retains the template/answer/source/output manifest and leaves the original byte-identical. The common Excel renderer marks only mapped string cells as literal strings, preserving exact stored answer text while leaving unmapped template formulas and layout untouched.

The shared shell supplies list/year/search/lexical similarity, pagination, source pickers, live source text, verbatim quote selection, exact number/unit selection, draft editing, separate model candidates, explicit Human reason/checkbox, revision/delete, import/export, original-template output and source navigation. API permissions gate every backend operation independently of UI visibility. A pending-operation gate consistently disables registered action controls, including dynamically rendered source/navigation controls and form submit buttons, until fresh record versions and trailing candidate reads finish; it rejects repeated handlers and preserves pagination readiness. Closing clears cached/pending state while retaining authorized navigation; generation tokens discard old success/error replies without clearing or unlocking a reopened module. The module also clears cached inquiry content on 401/403 or changed identity and discards late responses; inquiry API and inquiry-created originals use no-store responses. Common queued-session/shared-PC authorization hardening remains the separately tracked internal Task 11 across Run B modules, without replacing the canonical helper here.

## Validation boundary

Synthetic tests exercise forgery, confidentiality of answer prose/numbers, removed-source lineage, approval bypass, stale versions/SHA, exact Decimal/formula arithmetic, candidate isolation/outage/provenance, atomic CSV/Excel exchanges, template preservation and alternate common consumers. Fresh bootstrap is tested in an isolated subprocess. Dedicated opt-in CI tests execute actual Chromium and PostgreSQL source locks/concurrent confirmation/qualified-schema immutable triggers; local skips are explicitly not proof of those environments.
