# 職員・組織・人事履歴・アカウント管理

## 共通契約

職員はEmployee、ログインはUserとして分離する。業務モジュールは既存employee_idを参照する。組織と発令期間はorganization_units / employee_assignmentsで保持し、過去の所属を上書きしない。主所属は同一職員の期間重複を禁止し、兼務は許容する。日付は日本時間の日付、開始・終了とも当日を含む。

権限は明示した恒久UserRoleと、その日に有効な所属・発令のAssignmentRoleを合成する。退職・職員無効化はログインと既存セッションを拒否する。人事管理権限だけでは役割を付与できず、account.manageを別途要求する。system_adminは発令から付与できない。最後の有効な管理者を無効化・除去できない。

## 管理者操作

`/ui/admin.html`へブラウザでアクセスする。組織作成、職員登録、主所属・兼務発令、異動、所属終了、アカウント発行、役割変更、無効化、パスワード再設定、監査閲覧を行う。重要更新は人間による理由入力と確認を要求する。競合409時は再読込し、最新内容を確認して再入力する。

アカウントの初期パスワードは12文字以上。本人変更は現在のパスワードが必要。直近5件への再利用は拒否し、変更・再設定は全セッションを失効する。パスワードやハッシュはレスポンスと監査差分に出さない。

## 証拠と残件

基準main89e87e17（PR42を含む）。ローカル全backendテスト291成功、5skip。PostgreSQLの全migrationと期間重複EXCLUDEはCI実行対象であり、ローカルskipを成功と数えない。専用テスト9成功1skip。JavaScript構文確認済み。

既存の無効隊員テストは操作者自身を無効化していたため、新しい認証拒否が業務入力検証より先に動いた。有効な操作者と無効隊員を分離し、認証の保護を維持した。

本Sliceはパスワード期限、監査ページング、管理者アカウント名変更の完成を宣言しない。実LANの複数PC受入は別のExternal Gate。人工データのみをテストに使用し、実職員情報を登録しない。

レビュー修正: 役割付き所属の期間変更、職員・組織の有効状態変更にもaccount.manageが必要。ログインとアカウント更新はPostgreSQLの同一トランザクション排他を使用し、再設定前パスワードから更新後セッションを発行しない。履歴は現在＋過去5世代を拒否する。アカウント管理だけの担当者はaccount-staffの職員ID・氏名・コード・状態の限定一覧を利用し、personnel.readを要する詳細一覧は取得できない。

ローカル実ブラウザは環境のUnixソケット制約で起動不可。CIのadministration-browserジョブがHTTP/Chromiumで組織・職員・辞令・アカウント・監査・ログアウトを確認し、人工データ画面をartifactとして保存する。Green確認前に画面完成とは記載しない。

レビュー修正後のローカル統合検証: 297件成功、6skip、168warnings。skipにはPostgreSQLと実ブラウザの別CI環境が含まれる。
